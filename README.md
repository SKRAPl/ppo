# Таблица ППО — на GitHub Pages, с общими (не локальными) правками

Это тот же сайт, что и раньше (дизайн, вёрстка, `styles/style.css`,
`scripts/script.js` — не тронуты, диф с оригиналом только добавляет
`id="data-block-…"` на 30 существующих блоков и один пункт в футере,
подробности в самом низу этого файла). Главное изменение по вашей просьбе:
**данные и пользователи теперь хранятся не в localStorage браузера, а прямо в
репозитории** (`data/manifest.json`, `data/categories/*.json`,
`data/users.json`) — значит, правки видят все посетители сайта на GitHub
Pages, а не только тот, кто их сделал.

## Важно исправлено

В прошлой версии при выгрузке данных пропали пустые "прокладки" между
группами карточек (3-я колонка в сетке купить/продать) — из-за этого вся
раскладка съезжала, как на вашем втором скриншоте. Сейчас это починено:
пустые карточки сохраняются как есть, раскладка — один в один как в
оригинале.

## Как это развернуть на GitHub Pages

1. Скопируйте содержимое этой папки в ваш репозиторий (замените файлы —
   `styles/`, `scripts/`, `images/` и сам `index.html` совместимы с тем, что
   у вас уже есть, просто добавлены `data/`, `js/`, `admin.html`, `css/`,
   `.nojekyll`).
2. Закоммитьте и запушьте в ветку, с которой у вас включён GitHub Pages
   (обычно `main`):
   ```
   git add .
   git commit -m "Добавлена админка и общие данные"
   git push
   ```
3. В настройках репозитория (Settings → Pages) должно быть указано
   "Deploy from a branch" → нужная ветка → `/ (root)`. Если Pages уже был
   включён раньше — ничего менять не нужно.
4. Через 1–2 минуты сайт обновится на вашем `https://<логин>.github.io/<репозиторий>/`.

## Как подключить админку к записи (GitHub-токен)

Просто зайти под `PolkaX` можно сразу — логины и пароли читаются из
`data/users.json`, который уже лежит в репозитории. А вот чтобы что-то
**сохранить** (добавить фразу, создать пользователя и т.д.), админка должна
уметь коммитить в репозиторий от вашего имени — для этого один раз вводится
токен:

1. GitHub → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens** → Generate new token.
2. Repository access → **Only select repositories** → выбрать именно этот
   репозиторий (не давайте доступ ко всем!).
3. Permissions → **Contents** → **Read and write**. Больше ничего не нужно.
4. Скопировать токен и в админке нажать на плашку «GitHub не подключён» в
   шапке страницы → вставить владельца/репозиторий/токен → «Проверить» →
   «Сохранить».

Токен хранится только в localStorage вашего браузера и отправляется только
напрямую в `api.github.com` — в репозиторий не попадает и другим
посетителям не виден.

**Каждое действие в админке (фраза, категория, пользователь) — это отдельный
коммит** в репозиторий. GitHub Pages пересобирает сайт автоматически, обычно
в течение минуты.

## Как теперь устроено добавление (это была главная проблема)

Раньше каждая карточка (например, новая машина) — это на самом деле 4 строки
(купить свободно/фикс, продать договорная/фикс) плюс пустая "прокладка" между
ними. Раньше их приходилось добавлять по одной и сохранять по отдельности, а
при добавлении/удалении прокладки съезжали или оставались висеть пустыми.

Теперь админка это понимает: для категорий с парой купить/продать (Рыба,
Автомобили, Одежда, Диски, Флаги и т.п.) в форме добавления — только одно
поле «Название», и сразу видно превью, какие 4 строки получатся. Один клик —
и в репозиторий уходит один коммит с готовой карточкой. Удаление стирает всю
карточку целиком, никаких пустых клеток не остаётся.

Категории без такой пары (Номера, Отказы, Полезное, Услуги — там нет
структуры «купил/продал одно и то же») остаются как раньше: список
отдельных строк, добавляются/редактируются по одной.

Есть и третий, редкий случай: несколько десятков строк по всем категориям
(в основном — опечатки в исходных данных вроде пропущенной точки, плюс
вступительные заметки типа "можно указывать размер склада") не укладываются
в шаблон купить/продать — они не потерялись, а остались обычными
редактируемыми строками (кнопка «+ дополнительные варианты добавления» под
полем «Название» — там же три способа добавить нестандартное):
- **обычная строка** — просто произвольный текст;
- **пустая клетка** — вставить визуальную "прокладку" между блоками, если
  собираете раскладку вручную;
- **пара купить/продать вручную** — мини-форма, которая соберёт стандартные
  4 строки + прокладку из вашего текста (например, с размером склада или
  числом гаражных мест) и фиксированной суммы.

## Изменения копятся, коммит — по кнопке

Внутри одной категории все добавления/правки/удаления сначала копятся
локально (черновик — видно жёлтую плашку «Есть несохранённые изменения» и
оранжевую точку рядом с категорией в меню) и никуда не отправляются, пока вы
сами не нажмёте **«Сохранить изменения»** — тогда всё разом уходит одним
коммитом в репозиторий. Кнопка **«Отменить всё»** рядом откатывает черновик
целиком. Черновик переживает перезагрузку страницы (хранится в этом браузере
до сохранения), так что случайно закрытая вкладка ничего не потеряет — но
пока не нажата «Сохранить», на самом сайте и у других людей изменений не
будет видно.


Это статический сайт без сервера, поэтому есть особенности, которые стоит
учитывать заранее:

1. **`data/users.json` — публичный файл.** Как и весь остальной код сайта,
   он открыт всем через GitHub Pages. Пароли там не хранятся в открытом виде
   (только SHA-256 хэш с солью), но раз список логинов и хэши физически
   лежат в публичном репозитории — не используйте для этих учётных записей
   пароль, которым пользуетесь где-то ещё.
2. **Права в админке (кто что может редактировать) — это ограничение только
   интерфейса, не GitHub.** GitHub-токен с правом записи даёт доступ ко
   ВСЕМУ репозиторию — GitHub не умеет ограничивать токен одним JSON-файлом.
   Поэтому реально «жёсткая» граница — это у кого ЕСТЬ токен с доступом к
   репозиторию, а не что вы отметили галочками в правах пользователя. Права
   по категориям в админке полезны, чтобы люди не путались и не трогали
   лишнее по интерфейсу, но не заменяют доверие к тому, кому вы выдаёте
   токен. Каждый администратор должен создать **свой** токен в своём
   аккаунте (если у него есть доступ к репозиторию как у соавтора) — тогда
   хотя бы видно в истории коммитов, кто что менял.
3. Если нужна по-настоящему серверная модель прав (когда токен GitHub видит
   только сам сайт, а не люди с доступом к админке) — это требует отдельного
   маленького бэкенда (например, serverless-функция, которая держит токен у
   себя и проверяет права перед тем, как что-то менять). Могу собрать
   отдельным шагом, если понадобится.
4. Открыть `index.html`/`admin.html` двойным щелчком (`file://`) не
   получится — `fetch()` данных из `data/` не работает без веб-сервера. Для
   локальной проверки перед пушем запустите что-то вроде
   `python3 -m http.server` в этой папке и откройте `http://localhost:8000`.

## Структура

```
index.html, styles/, scripts/, images/    — ваш оригинальный сайт, не изменён
                                             (кроме id на 30 блоках + 1 пункт в футере)
admin.html                                 — новая страница администрирования
data/
├── manifest.json                          — список категорий
├── users.json                             — пользователи и права
└── categories/<slug>.json                 — { template, blocks } — шаблон
                                              купить/продать (если есть) и
                                              список карточек/строк
js/
├── github.js                              — коммиты в репозиторий через GitHub API
├── store.js                               — категории и фразы (чтение всем, запись — через github.js)
├── auth.js                                — пользователи и права (аналогично)
├── sync.js                                — подставляет данные в существующую вёрстку сайта
└── admin.js                               — логика страницы admin.html
css/base.css, css/admin.css                — стили только для admin.html
```

## Что именно изменено в `index.html` (для сверки)

Ровно три вида правок, больше ничего:
1. 30 существующим блокам категорий добавлен `id="data-block-<slug>"`.
2. Один новый пункт в футере («Админка ППО» → «Войти»), теми же классами,
   что и остальные колонки футера.
3. Три `<script>` тега перед `scripts/script.js` (которые загружают данные) —
   сам `scripts/script.js` и `styles/style.css` не тронуты ни на байт.
